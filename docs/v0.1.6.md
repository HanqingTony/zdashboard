## 二、事实源与操作层的分工（重要）

| 层 | 在哪 | 谁说了算 |
|---|---|---|
| **事实源** | `zpa` 的 `PROJECTS.md` / `IDEAS-RANKING.md` / `PORTFOLIO.md` | 清单变了 → 点「**从清单导入**」（按 `name` 幂等 upsert） |
| **操作层** | zdb.db 的 `zproject` 表 | 状态 / 下一步 / 备注 / 风险 / 想法判决（活·搁·死）在页面里改，**导入不会覆盖**这些字段（`COALESCE(NULLIF(现有值,''), 新值)`） |
| **派生字段** | git 读出来的（最近提交/脏/未推送/远端） | 点「**同步 git**」刷新（19 个仓库） |

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/projects?kind=&board=&layer=&status=&grade=&verdict=&q=` | 列表 + 统计 |
| POST | `/api/projects/import` | 跑 `src/projects/fromMarkdown.js` 重新生成 seed 再导入（`?regen=0` 跳过重新生成） |
| POST | `/api/projects/sync` | 刷新 git 派生字段 |
| POST / PATCH / DELETE | `/api/projects[/:id]` | 新建 / 改（白名单字段）/ 删 |

### 表结构要点

`zproject(name UNIQUE, kind, board, layer, status, feasibility, completeness, importance, score, grade,`
`verdict, stack, repo_path, remote, deploy, ports, next_step, risk, note, source,`
`last_commit_at, last_commit_subject, dirty, ahead, synced_at, pinned, created_at, updated_at)`

- `kind`：repo / infra / upstream / data / idea；`layer`：L0 在做 … L4 归档（L0 自动置顶）
- 想法的 `verdict`：`alive`（活）/ `parked`（搁）/ `killed`（死）——页面上三个小按钮，用来做「杀想法」流程；Tools 角标显示**待判想法数**（当前 94）

## 三、清单 → 库 的生成器

`src/projects/fromMarkdown.js`（Node）：解析 `zpa/PROJECTS.md` 的 5 张表 + `IDEAS-RANKING.md` 的 A/B/C/D 四张表 + `PORTFOLIO.md` 第四节的**风险表**，生成 `src/projects/seed.json`：

- 风险按**关键词+词边界**匹配挂到对应项目上（避免 `tether` 命中 `aBigfileTether`）
- `repo_path` 按名字猜 `/home/tony/zrepo/<name>`（存在 `.git` 才写）
- 名字规范化：去 `idea/`、`.md`、`/readme`、括号补充、尾斜杠

## 四、顺手修的真 bug

- **`tools/refresh-projects.sh` 生成非法 UTF-8**：shell 的 `cut -c` 在 C locale 下按**字节**截断，把汉字切成半个字节（PROJECTS.md 一度不是合法 UTF-8）。已把表生成整体搬到 **Node**（`tools/gen-repos-table.js`，`clip()` 按字符截断），`refresh-projects.sh` 只负责用 awk 替换区块。
- `zpa/IDEAS-RANKING.md` 补齐 2 条漏掉的想法（智能场景市场调研、事业-适老化定制）并写清覆盖口径（97 个 md → 94 条想法，流水线 3 篇算 1 条、`游戏-arpg` 已是项目）。
