# v0.1.3 更新记录

## 新增：信息聚合（Tools 新页面）

Tools 里新增 **📡 信息聚合**：每个关注对象一个**独立探针**，结果落库并标注「新」条目，
打开页面即知「有没有新东西」，不用自己挨个去翻站点。

| 源 id | 分组 | 关注点 | 探针实现 |
|---|---|---|---|
| `hf-qwen` | HuggingFace | Qwen 团队是否有新模型 | `GET hf-mirror.com/api/models?author=Qwen&sort=createdAt&direction=-1` |
| `hf-ornith` | HuggingFace | ornith(-ai) 是否有新模型 | 同上，`author=ornith-ai` |

> civarchive 的 `base_model` 写法不统一（`MiniMax H3` / `MiniMax-H3` / `MINIMAX_H3_COMFY` / `Minimax H3 Open`；
> `Qwen 2.1` / `Qwen-Image-2.1`），所以每个 LoRA 探针都自带**归一化正则**，只留 LoRA（`type=LORA`），再按创建时间倒序。

### 「新」怎么判定

- 表 `agg_item(source_id, item_id)` 记录**见过的条目**；`first_seen == last_seen` 即「新」（本次探测才第一次见到）。
- 于是：第一次探测 → 全部是「新」；之后再探测 → 老条目只更新 `last_seen`，`新` 数归零，直到真的出现新条目。
- 首次进入页面若数据过期（TTL 30 分钟）或从未探测，前端自动跑一次刷新（只自动一次，避免反复打外部站点）。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/agg` | 读缓存（含 `isNew`、`stale`、各源 `status/error`、`totalNew`） |
| POST | `/api/agg/refresh` | 跑探针（`?source=<id>` 可只跑一个），写库后返回最新快照 |

### 设计要点

- **每个源独立逻辑、独立失败**：某源超时/改版只影响自己（`status=error` + 错误文本），其余照常显示；同源并发刷新会被合并（in-flight 去重）。
- **只走直连**：实测 `civarchive.com` 与 `hf-mirror.com` 直连可用（`huggingface.co`、`civitai.com` 直连 000，需代理），
  因此 zdashboard 的 systemd 单元**不需要**代理环境变量；HF 一律走 hf-mirror（卡片链接也指 hf-mirror，浏览器免代理可开）。
- 表：`agg_item`、`agg_state`（建在既有 `zdb.db`；写完 `wal_checkpoint(TRUNCATE)`，沿用项目约定）。
- 加源只需在 `src/agg/sources.js` 里加一条（`{ id, group, label, note, homepage, probe }`），前端自动多一张卡。

### 文件
