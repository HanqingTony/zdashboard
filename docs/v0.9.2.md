# v0.9.2 — Ask 接入 Herdr：问题直接进正在运行的 Pi TUI

## 问题

v0.9.0 / v0.9.1 的本地 Pi 是“复制 session 到临时目录，另起一个 `pi --session` 回答”。它只能读取上下文，无法把问题显示在用户正在看的 Pi TUI 里。Pi 的 TUI 只在内存中维护当前分支，不会监听外部对 session JSONL 的追加，所以页面上的提问不可能靠写 session 文件“同步”过去。

## 方案

Ask 的 Pi 引擎现在先查 Herdr 的实时 agent 列表：

1. 根据所选 session 的绝对路径匹配 `herdr agent list` 里的 `agent_session.value`
2. 命中且不是 `blocked`：调用
   `herdr agent prompt <pane_id> <question>`
   问题会像用户在 TUI 里输入一样提交，并显示在对应终端
3. 没命中（没有 Herdr / 这个 session 没开 TUI / pane 已退出）：回退到原来的只读副本回答
4. TUI 正在等待确认：返回 409，请用户先在终端处理

不直接写 session JSONL，避免和正在运行的 Pi/ACP 进程并发写坏文件。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `HERDR_BIN` | `~/.local/bin/herdr` | Herdr CLI 路径 |
| `HERDR_SYNC` | `1` | 设为 `0` 关闭 TUI 转发，全部走只读副本 |
| `HERDR_TIMEOUT_MS` | `8000` | `agent list` / `agent prompt` 超时（毫秒） |

Herdr 的 socket、Pi session 路径和 CLI 都在服务用户 `tony` 的 home 下；`ProtectHome=read-only` 下已验证 `herdr agent list` 可正常连接 socket。

## 验证

- `test/ask-api.test.js` 用假 Herdr 覆盖：session 列表标记 `live`、把问题以 `wT:p1` 为目标提交、problem 文本进入 prompt 参数
- `npm test`：45/45
- 无实时 TUI 时原有“只读副本 + 大 session 截取”路径不变
