# v0.5.0 — 双推逻辑补齐：自动创建 GitHub + Gitee 仓库

发布日期：2026-10-27

之前“双远端”只配置了两个 push URL，没有创建远端仓库，导致 push 时 Gitee 404。这一版把建库纳入双推逻辑。

## 新脚本

```bash
npm run remotes:create -- <name> --private --repo /home/tony/zrepo/<name> --push
```

脚本会：

1. 检查/创建 GitHub 仓库（本机 `gh` 登录态）
2. 检查/创建 Gitee 仓库（Gitee OpenAPI）
3. 配置 `origin`：fetch GitHub，pushurl GitHub + Gitee
4. 可选：分别推送 `main` 到两端，逐端报告成功/失败

参数：`--public`、`--description X`、`--repo PATH`、`--push`。

## 凭据

- GitHub：本机 `gh`（`~/.config/gh`）
- Gitee：`/home/tony/zdata/zdashboard/gitee.env`（600）里的 `GITEE_TOKEN` / `GITEE_OWNER`
- **token 没有写进仓库**，`.gitignore` 已排除 `gitee.env`

## PM 自动建远端

项目管理的「+ 仓库 / + 新建项目」现在在勾选双远端时：

- 创建本地仓库 + 初始提交
- 自动调同一套 `src/pm/remotes.js` 创建 GitHub/Gitee 仓库
- 配双推并推送初始提交
- 任一端失败不会阻止本地仓库创建，但会在页面提示里列出失败原因
- 设置 `PM_CREATE_REMOTES=0` 可关闭自动建远端（测试/离线）
