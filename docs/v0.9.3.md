# v0.9.3 — 修复 PM nginx path unit 自我触发

## 问题

`zdashboard-nginx-apply.path` 同时配置了：

```ini
PathChanged=.../pm-nginx.conf
PathExists=.../pm-nginx.conf
TriggerLimitIntervalSec=0
TriggerLimitBurst=0
```

`PathExists=` 是“只要文件存在就满足”的条件。oneshot service 退出后，path unit 仍然满足条件，于是立刻再次启动 service，形成约 120ms 一轮的无限 self-trigger。

后果：systemd 与 nginx 持续占用 CPU，每秒多次 reload nginx，journal 被快速写满。

## 修复

- 只保留 `PathChanged=`，删除 `PathExists=`
- path unit 增加触发限流：`TriggerLimitIntervalSec=30` / `TriggerLimitBurst=10`
- service 增加启动限流：`StartLimitIntervalSec=30` / `StartLimitBurst=10`
- 新增 `test/deploy-units.test.js`，锁住“不得再出现 PathExists”和限流值

## 验证

- 停止旧 path/service 后重新安装 unit
- `pm-nginx-status.json` 只应用一次：`applied 2 project(s)`
- 等待 10 秒，path 保持 `active (waiting)`，service 保持 `inactive`
- `pidstat`：systemd / nginx CPU 均降到 0%
- `npm test`：47/47
