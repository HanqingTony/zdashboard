# v0.7.0 — 路线图改为画布式思维导图

## 为什么重做

v0.6.0 的路线图是「左侧目标列表 + 右侧纵向树」，适合看单条目标，但看不出多线并行，也无法表达“同一个项目服务多个愿景”。v0.7.0 把路线图改成一张可平移、缩放的 DAG 思维导图。

## 数据模型

迁移 **v8 `roadmap-mindmap-graph`**：

- `roadmap_graph_node`：`id / title / description / category / kind / status / target_date / completed_at / sort_order / created_at / updated_at`
  - `kind`：`vision`（愿景）/ `project`（项目）/ `task`（里程碑）
  - `status`：`todo / doing / done / blocked / paused`
- `roadmap_graph_edge`：`id / parent_id / child_id / sort_order / created_at`
  - 一个节点可以有 0..N 个上级；没有上级即为根节点
  - 删除节点只删除节点本身和它的连线；子节点会断开并上移为根节点，不级联删除

v7 的 `roadmap_goal` / `roadmap_node` 会在迁移时转换：

- 每个 goal → 一个 `vision` 节点
- goal 下的根里程碑 → `project`，更深层 → `task`
- 原 `parent_id` / goal 归属 → `roadmap_graph_edge`
- 旧表迁移完成后删除

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/roadmap` | 返回 `{ nodes, edges, stats }` |
| POST | `/api/roadmap/nodes` | 新建节点，`parentIds` 可空、可多个 |
| PATCH | `/api/roadmap/nodes/:id` | 编辑节点/状态/日期/分类，替换上级关系 |
| DELETE | `/api/roadmap/nodes/:id` | 删除节点，子节点上移为根节点 |

服务端会校验：标题/描述/分类长度、日期格式、kind/status 枚举、上级存在、最多 32 个上级、不能以自己为上级、不能移动到自己的后代下面。

进度不落库。前端对每个节点按 DAG 可达后代去重计算完成比；总完成度按全部节点中 `done` 的比例计算。

## 画布

- `public/roadmap.js` 负责布局、连线、平移缩放和增删改
- 横向思维导图：根节点在左，主分支向右展开；根按 `sort_order` 纵向排列
- 一个节点的第一条 incoming edge 作为主线布局，其余连线用虚线表示“多愿景/多上级关联”
- 每条根分支有独立颜色，节点左侧色条、连线和进度条沿用该颜色
- 拖动画布平移，滚轮/`＋−` 缩放，`⛶` 适应画布；双击节点编辑
- 节点详情在右侧 inspector：状态、日期、分类、描述、分支进度、上级、增删改
- 手机端 inspector 变为底部抽屉；断点变化时自动重新 fit，避免沿用桌面平移量
