## 一、调查结论：外网"有没有像国内那样直接拿的官方 API"？

**有，但分布很不均匀**——社交平台里"给免费官方 API"的只有 Reddit/YouTube/Mastodon/Bluesky，
**X/Twitter 是唯一的硬付费墙**；同时一批"指标型"官方接口（Google Trends / Wikipedia / GitHub / Hacker News）
完全免费且比社交平台更稳。下表全部为**本机实测**（直连 / 本机代理 都试过）：

| 候选 | 性质 | 实测 | 结论 |
|---|---|---|---|
| **Google Trends 每日热搜** `trends.google.com/trending/rss?geo=US` | **官方 RSS**，免 key | 200（RSS，10 条含搜索量） | ✅ **已接**（X trends 的首选替代指标） |
| **Reddit OAuth** `oauth.reddit.com/r/popular/hot` | **官方 API**，免费注册 app（100 QPM） | 需凭据 | ✅ 有凭据时走这条（可靠） |
| Reddit 官方 RSS `…/popular/hot/.rss` | **官方 feed**，免 OAuth | 200，**但会被限流 429** | ⚠️ 无凭据时退回这条（尽力而为：429 自动重试一次） |
| Reddit 免认证 JSON `…/hot.json` | 非官方用法 | 直连 000 / 走代理 **403** | ❌ 不可用 |
| **Bluesky 趋势话题** `public.api.bsky.app/xrpc/app.bsky.unspecced.getTrendingTopics` | **官方公共 API**，免 key | 200，10 条话题 + 说明 | ✅ **已接**（推特的同构替代） |
| **Mastodon 趋势标签** `mastodon.social/api/v1/trends/tags` | **官方公共 API**，免 key | 200，含今日帖数/人数 | ✅ **已接** |
| **Hacker News 头条** `hn.algolia.com/api/v1/search?tags=front_page` | **官方 Algolia API**，免 key | 200，含分数/评论数 | ✅ **已接**（科技圈头条指标） |
| **Wikipedia 当日最热条目** `wikimedia.org/api/rest_v1/metrics/pageviews/top/...` | **官方 API**，免 key | 200（数据有 1–3 天延迟） | ✅ **已接**（"世界在看什么"） |
| **GitHub 新星仓库** `api.github.com/search/repositories?q=created:>…&sort=stars` | **官方 API**，免 key（未认证 10 次/分） | 200 | ✅ **已接**（开发者趋势） |

| X 抓取型备选：Nitter | 第三方镜像 | `nitter.net/trends/…/rss` → **410 Gone** | ❌ |
| X 抓取型备选：getdaytrends | 第三方 | `/rss` → **301** | ❌ |
| X 抓取型备选：trends24.in | 第三方 | 页面 200，但**没有 RSS**（只 HTML） | ❌ 不采用（要写 HTML 抓取，脆弱且灰色） |
| 备用：Product Hunt 官方 RSS | 官方 feed | 200 | ⏸ 未接（备选） |
| 备用：Techmeme 官方 RSS | 官方 feed | 200 | ⏸ 未接（备选） |
| 备用：Google News RSS | 官方 feed（走代理） | 200 | ⏸ 未接（备选） |

**一句话**：X 拿不到（唯一付费墙，抓取路子也已全废）；但"推特在热什么"这件事可以用
**Google Trends（搜索热度）+ Bluesky（同构社交）+ Mastodon（联邦社交）** 这三个免费官方源近似覆盖，
再加上 **HN / Wikipedia / GitHub** 三个"硬指标"，实际信息量比单一 X trends 更大。

## 二、新增的 7 个免 key 源（`外网趋势` 分组）

`tr-gtrends`（Google Trends US）· `tr-reddit`（有凭据走 OAuth，否则 RSS）· `tr-bluesky` · `tr-mastodon` ·
`tr-hn` · `tr-wiki` · `tr-github`；`tr-youtube` 仍是**待配置**（只差 `YOUTUBE_API_KEY`）。

- 全部按榜单排名显示（`ranked: true`，显示前 10），「新」= 第一次出现在这个榜里的话题
- 代理策略：源上声明 `proxyMode` —— `'on'`（必须走代理：Reddit/Bluesky/Mastodon/YouTube）、
  `'auto'`（先直连，失败再走代理：Google Trends/HN/Wikipedia/GitHub）、默认直连（国内平台）

## 三、实现踩坑（值得记住）

1. **Node 内置 `fetch` 与 npm 装的 `undici` 不能混用 dispatcher**：把外装 `ProxyAgent` 交给全局 `fetch`
   会报 `fetch failed` / `cause: invalid onRequestStart method`（版本不一致）。**代理请求一律用 `undici` 自带的 `fetch`**
   （本仓库装的是 undici 8，Node 22 内置的是另一版本）。
2. **Reddit 免认证 JSON 被挡（403）、官方 RSS 会被限流（429）** → Reddit 想稳就得注册免费 OAuth app。
3. **Wikipedia pageviews 有 1–3 天延迟**：查"昨天"可能 404 → 实现里向前回退最多 4 天取最近可用的一天，并把实际日期写进条目 meta。
4. RSS 解析引入 `fast-xml-parser`（纯 JS，无原生依赖）。
