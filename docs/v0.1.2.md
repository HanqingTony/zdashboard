# v0.1.2 更新记录

发布日期：2026-10-15

## 新增：服务导航（黄页）

把原来 nginx 18100 的静态导航页（`/var/www/zportal/index.html`）重做为 zDashboard 的一个模块，
成为本机的**默认落地页**——打开 `https://192.168.0.102:18100/` 直接看到服务清单。

- **数据驱动**：内容全部在 `public/nav.json`（标题 / 分组 / 卡片 / 底部说明）。
  增删服务只改这个 JSON，刷新页面即生效，不必动代码。
- **卡片字段**：`name`、`url`、`desc`、`tags`（端口等小标签，可选）。
- **渲染**：`public/app.js` 的 `renderNavApp()`；样式在 `style.css` 的「服务导航（黄页）模块」段。
  卡片网格窄屏自动降为单列（`minmax(210px,1fr)` → 媒体查询 768px 单列）。
- **入口**：Tools 列表新增 `🧭 服务导航`（`data-app="nav"`），初始化时默认 `switchApp('nav')`。
- 内容与原静态页保持一致（对外 LAN 7 项 + 仅本机 3 项 + 端口约定说明），
  并补充「本页由 zDashboard 提供」的说明与端口小标签。

## 部署（zmain 本机）

- **后端常驻**：新增 systemd 单元 `zdashboard.service`
  （`/home/tony/zrepo/zdashboard`，`127.0.0.1:28100`，`DB_PATH=/home/tony/zdata/zdb.db`，
  `AUDIO_DIR=/home/tony/zdata/zdashboard/audio`）。
- **nginx 18100**：由 `root /var/www/zportal` 改为 `proxy_pass http://127.0.0.1:3100`
  （当日随「端口规范化」再迁到 `http://127.0.0.1:28100`：18xxx 对外入口 ↔ 28xxx 回环上游配对，见 zpa 仓库 `PORTS.md`）
  （保留 TLS，透传 `/ws` 的 Upgrade，`client_max_body_size 20m`）。
  改前配置备份在 `/etc/nginx/conf.d/zports-external.conf.bak-*`，旧静态页文件保留未删。

## 修复与整理

- `server.js`：恢复为可用入口（此前 `2.0building` 提交里是占位实现，可用版本存于 `server.bak.js`）。
  两处改动：静态目录改为**绝对路径**（`resolve(__dirname, 'public')`，不依赖启动 cwd）；
  新增 `GET /api/health`（回 `{ok,service,version,uptime}`，便于探活）。
- WebSocket 事件名与前端对齐：`{type:'status'}` → `{event:'sync'}`（前端 `app.js` 按 `event` 字段分发）。
  ⚠️ 仅对齐了事件名：`play` 事件的载荷仍是旧形状（`{id,path,addedAt}`），而前端期望 `{id,url,fileName}`，
  且后端没有音频文件流路由（`src/routes/audio.js` 只有列表/入队/跳过/清空）——音频模块本就是待删的遗留（见 v0.2.0 路线），本次未动。
- `package.json`：加 `allowScripts.better-sqlite3`（npm 12 默认拦截原生模块的 install script，
  不加则 `better-sqlite3` 原生绑定不编译）。
