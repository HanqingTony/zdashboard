# v0.9.1 — 修复 Ask 的本地 Pi

## 问题

选择本地 Pi session 后，页面返回「Pi 没有返回内容」或 `Pi 退出码 1`。生产日志里有两类原因：

1. 临时 Pi 配置目录复制了 `settings.json`，Pi 尝试重新安装 `npm:billion-context-pi`；生产 `ProtectHome=read-only` 下 npm cache 不可写，直接失败。
2. 较大的 Pi session（例如 14MB / 110 万 tokens）超过模型上下文窗口，Pi 自动压缩也失败，退出码为 0 但没有文本输出。

## 修复

- 临时配置目录只复制 `auth.json` / `models.json` / `models-store.json`，不复制 `settings.json` / `mcp.json`。
- session 小于 2MB 时直接复制；更大的 session 只保留最近的 system/user/assistant **文本**，丢掉工具结果和 thinking，再交给 Pi。这样不会把整段工具上下文塞进模型窗口。
- Pi 改用 `--mode json`，从 `message_end` 中提取最终回答；不再依赖默认文本输出。
- 返回 `compacted: true` 时，页面会提示「已自动截取最近上下文」。
- 仍然不写回原 session，也不执行工具：`--no-tools --no-mcp --no-extensions --no-context-files`。

## 验证

- 小 session：`PING → PING`，`compacted:false`
- 当前 14MB session：`BIG2 → BIG2`，`compacted:true`
- `npm test`：44/44
- 新增 `test/ask-api.test.js`：问题记录、session 列表、假 Pi 返回、超大 session 截取、无效 session。

## 说明

这是“读取所选 session 的上下文回答”，不是把新消息写回原 session。这样避免和正在运行的 Pi/ACP 进程并发写坏 session。若以后需要写回，应单独做锁和备份。
