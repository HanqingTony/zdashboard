# v0.2.0 — 全面修复（正确性 / 安全 / 性能 / 数据语义）

发布日期：2026-10-18

这一版没有新功能，目标是把 v0.1.x 快速演进留下的坑一次清掉：删掉已决定废弃的音频模块，修正前后端不一致，补上安全边界，并让信息聚合的「新」真正等于「你没看过」。

## 破坏性变更

- **删除音频模块**：`src/routes/audio.js`、`/ws` WebSocket、前端播放条、`AUDIO_DIR` 配置、`ws` 依赖全部移除。
  `AUDIO_DIR` 环境变量已无用（systemd 单元里的那行可删）。
- **`public/app.js` 改为 ES module**：新增按钮需要把处理函数挂到 `window`（文件末尾已有清单）。
- **依赖**：移除未使用的 `js-yaml` 与 `ws`；`express` 升到 4.22.3（`npm audit` 0 漏洞）。
- **数据库**：`agg_state` 新增 `last_ok_at` / `fail_count` / `opened_at`（自动 ALTER，首次升级用上次探测时间初始化水位）；`zproject.created_at/updated_at` 新写入改为 ISO UTC。

## 正确性

| 问题 | 修复 |
|---|---|
| 手机旋转/跨 768px 后应用消失 | `layout()` 检测断点变化并重渲染当前屏 |
| 文章列表永远「0 词」 | `/api/articles` 返回真实 `word_count` |
| 前后端分词器不一致 | 抽出 `public/tokenize.js`，后端入库与前端着色共用；纯数字不再算单词 |
| 删除文章后词库残留 | 级联删除后清理不再属于任何文章的孤立词；确认框文案改为真实行为 |
| `saveGit` 绕过 WAL 约定 | 改为 `saveGitMany()`：一次事务 + `checkpoint()` |
| seed 的 L0 置顶从未生效 | 修正 `assignLayers()` 顺序，L0 项目 `pinned=1` |
| 导入重写 `seed.json` 弄脏仓库 | 改为进程内 `buildSeed()`，不落盘；zpa 不可用时回退 seed.json |
| 时间格式混用 | 统一 ISO UTC（`src/lib/time.js`） |
| 坏 JSON 返回 HTML 栈 | 统一 JSON 错误处理 + `/api` 404 JSON + `x-powered-by` 关闭 |

## 安全

- `escHtml` 转义 `& < > " '`：修复项目备注/外部 feed 标题在 `value="…"`、`title="…"` 中的属性注入
- 外链统一走 `safeUrl()`：只放行 `http(s)` 与站内路径，挡掉 `javascript:` / `data:`
- 新增可选 `AUTH_TOKEN`：设置后除 `/api/health` 外的 `/api/*` 需要 `X-ZToken` 或 Bearer；前端支持 `?token=` 一次性写入 localStorage
- 单词/文章/project id 参数校验；PATCH 增加 status/layer/verdict 枚举与 F/C/I 1–5 校验
- `decodeURIComponent` 二次解码导致 `URIError` 的问题修复
- 依赖审计：5 个漏洞（1 critical）→ 0

## 性能 / 事件循环

- 「同步 git」：`execFileSync` → 异步 + 并发 4；每仓库 7 次 git 调用压缩到 3 次。实测 19 仓库从阻塞 1.6s 降到非阻塞 ~0.14s
- 「从清单导入」：`execFileSync(node)` → `process.execPath` 的替代方案：直接进程内解析（顺带解决 systemd 下 `node` 不在 PATH 的问题）
- WAL checkpoint 增加 `throttle`（500ms 合并）与 `always`/`off` 三档：点一个单词不再每次 fsync；容器保持 `always`
- 聚合全量刷新并发上限 4；前端逐源增量刷新（并发 3）并单卡回填，不再等 18 个源全部返回才重绘
- `stateOf()` 不再每个源全表扫；新条目判定用 `INSERT OR IGNORE` 的 `changes`，去掉 N+1 查询

## 信息聚合语义

- **「新」改为未读**：`first_seen >= opened_at`；离开聚合页时打水位，Tools 角标清零
- 失败与成功时间分开：`last_ok_at` 决定 stale；`fail_count` 驱动指数退避（60s → 30min）
- 保留策略：热榜类每源最近 200 条；其余源 90 天未再见删除（索引 `(source_id,last_seen)`）
- 首次升级会把历史 800+ 条按上次探测时间设为已读，避免角标突然爆表（保留上次探测的 new 数语义）

## 前端

- 侧栏 Projects/Tools 由 `APPS` 配置生成，消除竖屏/横屏两份硬编码漂移
- 聚合刷新失败不再把按钮永久卡在 `…`；单源失败回滚该卡
- 单词点击失败会回滚颜色（不再乐观更新后撒谎）
- `pjApi` 显示服务端错误文本；`Empty` 项高亮修复（`data-app=""`）
- 静态资源 URL 带 `?v=<version>`，部署后不再吃旧缓存
